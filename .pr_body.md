Deletes the Gumroad admin web UI (React pages under `/admin`, their controllers, routes, views, presenters, specs), keeping every `Admin::`-adjacent endpoint that is consumed programmatically. This PR doubles as the issue per Sahil's directive — no separate issue.

## Why

The admin web UI is effectively unused:

- **Admin action tracking** (`AdminActionCallInfo`, since ~Aug 1 reset): **33 total calls**, only **6 distinct actions** ever touched:
  - `Admin::UsersController#show` (20)
  - `Admin::PurchasesController#show` (6)
  - `Admin::PurchasesController#undelete` (2)
  - `Admin::Users::MerchantAccountsController#index` (2)
  - `Admin::Users::PayoutInfosController#show` (2)
  - `Admin::Users::StatsController#index` (1)
  - **~94 other tracked actions: zero calls.**
- **Team web sign-ins**: Sahil May 8, Ershad May 19, everyone else older. All admin operations now run through gumclaw (audited prod console reads + `gumroad admin` CLI / API writes).

## What is KEPT (programmatic surface) — inventory

| Kept | Consumer / why |
|---|---|
| `app/controllers/api/internal/admin/**` (auth, whoami, purchases, licenses, sendgrid_emails, users, payouts, scheduled_payouts, products) + their routes in `config/routes.rb` | The `gumroad-admin` CLI (antiwork/gumroad-cli) — verified: its client prefixes every call with `/internal/admin` (`internal/adminapi/client.go`), and its commands hit purchases/users/payouts/scheduled_payouts/products/licenses/sendgrid/auth endpoints. This is also the surface that replaced the retired Helper tools API. |
| `AdminApiToken`, `AdminApiAuthorizationCode` models + OAuth admin-authorization flow in `Oauth::AuthorizationsController` | CLI login (`gumroad auth login`) exchanges an admin authorization code for a token. |
| `Admin::RelatedUsersService`, `Admin::UserRiskStatePresenter`, `Admin::ScheduledPayoutEnrichmentService`, `Admin::ScheduledPayoutPresenter`, `Admin::Users::ListPaginatedProducts` | Referenced directly by kept `Api::Internal::Admin::*` controllers. |
| `/admin/impersonate` + `/admin/unimpersonate` routes and the `Impersonate` concern (slimmed `Admin::BaseController`) | `Api::Internal::Admin::UsersController` emits `admin_impersonate_url` in its payload; `ApplicationController` depends on `impersonating?`. |
| Sidekiq Web + Flipper UI mounts under `/admin` | Ops tooling, not the React admin UI; still used (deploys, flag rollouts). |
| `AdminMailer` | Sent from `Charge::Disputable` and `User::LowBalanceFraudCheck` — independent of the UI. |
| `spec/routing/api_internal_admin_contract_spec.rb` | Pins the kept CLI endpoint contract. |

## What is DELETED

- `app/javascript/pages/Admin/**`, `app/javascript/components/Admin/**`, `app/javascript/packs/admin.ts`/`admin.scss`
- `app/controllers/admin/**` (47 web controllers) except the slim impersonate shim
- `config/routes/admin.rb` web routes (users, products, purchases, affiliates, search, payouts, sales reports, compliance, block/suspend forms, api_tokens page, action_call_dashboard)
- `app/views/layouts/admin*`
- UI-only `Admin::` presenters (user card/product presenters, merchant account, payment, purchase, unreviewed user), `Admin::UnreviewedUsersService`, `CacheUnreviewedUsersDataWorker` (+ schedule entry), `Admin::SalesReport`
- `AdminActionCallInfo` tracking: model, `AdminActionTracker` concern, `ResetAdminActionCallCountsJob` (+ schedule entry), action-call dashboard — nothing else reads it (its own numbers, above, justify the deletion)
- All UI-only admin controller/request/JS specs

## Break-glass

Human fallback is the audited prod console + `gumroad admin` CLI over SSH — Sahil and Ershad both have access. Admin token revocation: `gumroad auth logout` (server-side revoke via `POST /internal/admin/auth/revoke`) or console; the `/admin/api_tokens` page is deleted.
