Adversarial review brief for gumroad#7680 (branch `gp2648-pending-verification-remediation`, base `origin/main`).

Two changes to `app/controllers/settings/payments_controller.rb`:

1. `stripe_account_has_open_requirements?` gained a second branch: after the six requirement lists
   come back empty, it defers to `stripe_review_has_no_exit?` — `requirements["pending_verification"]`
   present AND `charges_enabled` false AND `errors` empty AND `current_deadline` blank. When true, the
   existing `#remediation` code mints a Stripe `account_update` AccountLink instead of redirecting the
   seller to `/settings/payments`, which is the only self-serve door the seller has.
2. `nothing_open_flash`'s paused-by-Stripe alert dropped its final sentence, which promised the seller
   that support would chase Stripe.

Attack these specifically, and say plainly if any is not a real problem:

- **The predicate's population.** Is there a reachable Stripe account class where
  `pending_verification` is non-empty, charges are disabled, `errors` is empty and there is no
  deadline, and where offering an `account_update` link is the WRONG outcome rather than the right
  one — e.g. a state that clears itself, or a rejection/appeal path that the earlier short-circuits in
  `#remediation` do not catch first? Name the account class if so.
- **Whether it can catch the ordinary case.** The reassuring behaviour must survive for the majority
  of `pending_verification` accounts (submitted, under review, nothing owed). Is any clause too weak
  to keep that promise?
- **Ordering against the earlier short-circuits.** `#remediation` returns before this check for a
  blank stripe account and for a rejected account with no local request. Does the new branch fire for
  a `stripe_rejected?` account that should have been short-circuited, or otherwise reach a state the
  earlier guards meant to exclude?
- **The copy.** Does dropping "please contact support and we'll chase it with Stripe" leave a seller
  with a genuinely open Stripe pause and no route at all? Is "There's nothing for you to submit right
  now" true for every state that renders it (it also renders from `#verify_stripe_remediation`)?
- **Interaction with `#verify_stripe_remediation`.** It is unchanged. With the new branch, a seller
  can now go out to Stripe and come back to a flash from that action. Is the resulting pair of
  messages coherent, or does it claim "nothing for you to submit" immediately after offering a page
  to submit on?
- **Do the specs bite.** `spec/controllers/settings/payments_controller_spec.rb` at the
  `pending_verification Stripe cannot finish` context: are any of them vacuous, and does each asserted
  clause of `stripe_review_has_no_exit?` have an example that fails when that clause is removed?
