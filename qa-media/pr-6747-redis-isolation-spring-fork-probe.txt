Captured output of qa-media/pr-6747-redis-isolation-spring-fork-probe.sh, against a Redis
started with 64 databases on port 6399.

`bin/rails` and `bin/rspec` both load `bin/spring`, so this is what the repo's default local
test commands actually do. Spring preloads the app once per checkout and forks each command
from that one process.

== BEFORE — the block leased at boot is inherited by every command

  Two concurrent commands from ONE spring server (bin/rails goes through bin/spring):
  [test-redis-isolation] slot 0 → Redis databases 14, 15, 16, 17 on localhost:6399
    app=14 sidekiq=15 rack_attack=17
    app=14 sidekiq=15 rack_attack=17

One lease, one block, two commands. Both call `flushdb` on database 14 before every test, so
they erase each other exactly as two runs on `.env.test` did — but now each holds what looks
like a valid lease, which is the harder version of the bug to find.

== AFTER — Spring.after_fork re-leases per command

  Two concurrent commands from ONE spring server (bin/rails goes through bin/spring):
  [test-redis-isolation] slot 0 → Redis databases 14, 15, 16, 17 on localhost:6399
    app=18 sidekiq=19 rack_attack=21
  [test-redis-isolation] slot 1 → Redis databases 18, 19, 20, 21 on localhost:6399
    app=22 sidekiq=23 rack_attack=25
  [test-redis-isolation] slot 2 → Redis databases 22, 23, 24, 25 on localhost:6399

Slot 0 is the spring server's own lease from preload. Each command then takes the next slot
and re-points its stores, so the two commands run on 18-21 and 22-25 with nothing shared.

Two things this needed beyond claiming a new slot:

  - The re-lease reads the endpoints as they were at boot, not the live ENV. Boot has already
    rewritten those vars to a leased block and the floor is derived from them, so deriving
    again per fork walked the floor up: slots landed on 14, 22, 26 instead of 14, 18, 22.

  - `Sidekiq.configure_client` only merges options. The internal pool is memoized on first
    use (sidekiq-7.3.0 `config.rb:137`), so without clearing it a command kept enqueuing to
    the database it inherited while holding a lease on a different one.
